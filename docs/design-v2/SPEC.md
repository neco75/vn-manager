# UI v2 — 実装仕様

## 1. 優先順位と設計の目的

対象は既存VN Manager全体のUI刷新。訪問者は作品を眺め、遊んだ状況を短い操作で記録する。
本書の確定仕様 → 担当Issueの作業範囲 → 採用画像 → 旧design.mdの順で読む。
Issueで本書と矛盾する設計変更を独断で選ばない。不足が実装を左右する場合は具体的な一点を報告する。
実装順の境界は「今回触る範囲」であり、後続Issueの機能を先に削除する理由ではない。

- 一覧は「探す・選ぶ」。詳細は「確かめる・書く・保存する」。
- 全体の記録情報を表紙で埋めない。表紙は作品を識別するために使う。
- 常用する再開メモと感想を最初の記録領域へ。外部のあらすじは折り畳む。
- 現在あるデータと機能を保つ。架空のアカウント、同期、通知、プレイリスト、進捗%を作らない。
- 日本語を既定とし、既存の英語切替も維持。新しいコピーはlib/translations.tsの両言語へ。

## 2. 視覚の基準

背景は冷たい白、面は白、選択面は薄いラベンダー。色の主役は作品の表紙。
フォームと本文は不透明。ユーザーの設定背景は既存のぼかしを維持して装飾層だけに置く。
発光、グラデーション文字、カードの拡大、スクロールに応じた登場アニメーションは採用しない。

既存app/globals.cssのsemantic変数へ集約し、ページごとの同じ色の直書きや新しいテーマ基盤を増やさない。

## 3. 共通の画面枠

| 幅 | ナビゲーション | 内容 |
| --- | --- | --- |
| 320〜639px | 高さ56pxのstickyヘッダー + メニューボタン | 左右16px、一列フォーム、カード2列、gap12px |
| 640〜1023px | 同ヘッダーと既存Dialogのメニュー | 左右24px、カード3列、gap16px |

サイドバーは画面高、長い場合は内部を縦スクロール。本文はmin-width:0。
モバイルメニューは既存Radix Dialogを再利用し、開いたらfocusを移し、閉じたらボタンへ戻す。
mainは一つ。PCに新しい横ナビを重ねない。低い画面高でナビ項目が見切れない。
メニューはライブラリ(/)、作品を探す(/search)、ランキング(/ranking)、統計(/stats)、設定(/settings)だけ。
/vn/[id]もライブラリ項目を選択状態にする。検索から開いた詳細でも本文の戻り先は検索条件を保持する。
aboutへの既存URLを残し、設定の「このアプリについて」からアクセス可能にする。
言語と画像ぼかしはPCサイドバー下部、モバイルメニュー内へ。宣伝・ユーザー情報は置かない。
stickyヘッダーz30、保存バーz20、Dialogz50。全幅で横スクロールを作らない。

## 4. ライブラリ /

DOMと見た目の順序: 見出し・件数・作品を追加 → 検索 → 状態/所有フィルター → sort/view → 一覧。

- 作品を追加は/searchへ。登録済み作品の検索とVNDB検索を混同させない。
- PCの状態フィルターは「すべて」「プレイ中」「プレイ予定」「クリア済み」「その他」。
  その他で一時中断・中断・動画勢を選べる。スマホは全状態を一つのSelectで選ぶ。
  現行6状態を4状態に減らさない。状態別の件数は現在の保存済み全件から計算。
- 所有フィルターは名前付きSelect。「すべて / 未設定 / 所有済み / 欲しい」を既存値に対応。
- 現行の並べ替え12通りとgrid/list/shelfを維持。既定はadded_desc。
  画像の「最近更新した順」はサンプルであり、新しいsort値を追加しない。
- 検索条件ありは「一致N件 / 全M件」。検索語・状態・所有・sort・viewは既存URLキーを使う。
- カードの順序: 表紙 → タイトル2行 → ブランド1行 → 状態と自分の評価。
  自分の評価は0〜100の整数か未評価。ライブラリカードにVNDB点数を重ねない。
- 画像枠は3:2、object-fit:contain。縦長のパッケージを横へ引き伸ばしたり文字をcropしない。
  白い余白は許容。画像なしでも同じ枠とタイトルを保つ。安全性判断はshouldBlurImageを使う。
- カード全体が一つの詳細Link。メニューボタンや入力をそのLinkに入れ子にしない。
  モックの三点メニューは実装しない。既存詳細で管理できるため不要。
- カード内のメモ・保存・記録するボタンを置かない。選択すると/vn/[id]へ進む。
- ルーレットは一覧ツールの「次に遊ぶ作品を選ぶ」という補助操作。現行の対象判定を変えない。
- リストは48×72px表紙、全文ではなく2行タイトル、状態・評価。スマホはタイトル下に情報を折り返す。
- 本棚は既存ShelfViewを継承し、画像なし・ぼかし時にもタイトルを識別可能にする。

## 5. 遷移と戻る

新しい/libraryや/library/[id]ルートは作らない。現行/と/vn/[id]を使う。
一覧から詳細へは/vn/id?from=エンコードした一覧URL。lib/detail-return.tsで戻り先を検証する。

- 詳細に「ライブラリに戻る」。fromが検索なら「検索結果に戻る」。
- 外部URL、重複from、不正キーは/へ。履歴を推測する無条件router.back()へ置き換えない。
- 一覧のscrollYは出発時にsessionStorageへ、一つの直前一覧URLとセットで保存。
  内容は{path, scrollY}のみ、キーvn-manager-library-return-v1。パス一致・有限非負値を検証。
  同じ一覧に戻ったとき、データとカードの配置が確定してから一度復元。条件を変えたら以前の位置を使わない。
  復元は上限へclampし、失敗したら通常表示へ。sessionStorage不可でも記録・遷移を妨げない。
- Browser Back/Forwardと画面内戻るの両方を確認。無関係な再レンダーでscrollを戻さない。
- 検索結果の既存snapshot・scroll復元・load moreを維持し、上書きしない。
- 新しいタブの直接詳細アクセスは/へ戻る。scrollを推測しない。
- 未保存値の保護は現行下書き・beforeunloadを維持。独自の履歴制御基盤は追加しない。

## 6. ライブラリ詳細 /vn/[id]

PC: 戻る → 左に表紙、右にタイトル/ブランドと記録。
左32%（最小220px、最大360px）、右は残り、gap32px。表紙は3:4の枠にcontain、最大高さ560px。
1024〜1279pxでは右側の小項目を2列、1280px以上はステータス・評価・時間を3列。
1024px未満は一列。表紙は80×120px、タイトルはその右。入力中にもタイトルを識別できる。

記録領域の順序:

1. ステータス、評価、プレイ時間。見えるラベルと現行値。
2. 再開メモ。常時表示、1行入力、maxLength200。
3. 感想(review)。既存MarkdownEditorで「書く / プレビュー」。PCの初期入力面min-height160px、スマホ144px。
4. 「メモ（自分用）」の折り畳み。notesを独立した既存MarkdownEditorで編集。
5. 「記録の詳細」の折り畳み。所有状況、開始日、クリア日、最終プレイ日、購入先。
6. 保存状態と「記録を保存」。新規未登録なら「ライブラリに追加」。
7. 「作品情報を見る」の折り畳み。あらすじ、原題、発売日、VNDB評価、タグ、画像、外部リンク、背景設定。
8. 「ライブラリから削除」。保存から離した控えめな操作、作品名と失われる記録を確認。

PCの作品情報入口は表紙下。スマホでは記録と保存の後。どちらも既定で閉じる。
折り畳みの開閉で値を消さない。既存メモを感想へ移動・結合しない。
個人記録のMarkdown内の画像/リンクの扱いとエディターは既存の安全性を維持。
感想/メモに新しい1000字制限は作らない。主領域にSliderは置かず、既存score数値Inputを使う。
未評価解除/未評価に戻す操作を残す。0点は有効。時間は表示・入力が時間、保存値は分（12.5時間=750分）。
所有状態のデータはunknown / owned / wishlist。省略時でも読み込み済み値を維持する。
フォーム初期化が完了するまで保存不可。DB失敗の空値で保存済み記録を置き換えない。

## 7. 保存・下書き・状態

LibraryContext・lib/db.ts・detail-draftを引き続き使う。IndexedDBへの独自の直接書込を足さない。

| 状態 | 表示と操作 |
| --- | --- |
| 初期化中 | 読み込み中。編集・保存不可。0件/未評価と断定しない |
| 保存済み・未変更 | 保存済み。既存項目の保存disabled |
| 編集中 | 未保存。変更値を保持、保存可能 |
| 下書き保存済み | 下書き保存済み・記録には未反映。本保存扱いにしない |
| 保存中 | 保存中…。二重実行不可、入力値を保持 |
| 保存成功 | 記録を保存しました。DB成功後だけdirty解除 |
| 保存失敗 | 保存に失敗しました。入力内容を残したまま再試行できます。近くに表示、トーストだけにしない |
| 別タブとの競合 | 他のタブで変更されています。最新値を再読込して確認。入力と下書きを保持し、無断で上書きしない |
| 下書きあり | 復元 / 下書きを破棄を明示的に選ぶ。復元前の値を既定フォームへ混ぜない |
| 下書き書込失敗 | 下書きを保存できませんでした。入力は残し、本保存可能なら操作を残す |

recordVersion=2、DB_NAME=vn-manager-db、DB_VERSION=3、既存store、draft version=1、全localStorageキーを維持。
LibraryItemのvn/status/ownership/score/notes/review/playTime/purchaseLocation/startedOn/completedOn/lastPlayedOn/resumeNote/addedAt/updatedAtを保つ。
updatedAtを使う競合検出、metadataだけの更新、追加の重複防止、復元transactionを迂回しない。
DB再接続不具合#55は別の既存Issue。表示を隠して「解決」としない。公開前に修正取り込みと障害E2Eを確認する。

## 8. その他の画面

### 作品を探す /search

見出し→「VNDBから検索してライブラリに追加」の短い説明→ラベル付き検索Inputと検索ボタン→結果。
巨大バナーは不要。PCはライブラリと同じ4列、スマホ2列。
検索結果は表紙/タイトル/ブランド/発売年/任意のVNDB x.x/10。自分の評価と混同しない。
詳細への主リンクと「ライブラリに追加」は別要素。Linkにbuttonを入れない。
既定のplan_to_play/unknown/score nullで追加。既登録は登録済みと詳細への入口、記録を上書きしない。
追加中はそのボタンを無効化。失敗はその操作の近くへ。初期案内、0件、通信失敗を区別。
もっと見ると、詳細から戻る際の検索結果・取得済みページ・位置を維持。

### ランキング /ranking

「自分のランキング」。見出し→評価済み件数→順位/小表紙/タイトル/状態/自分の点数の行一覧。
PC: 順位48px、表紙48×72px、作品名flex1、状態、点数。スマホ: 順位32px、表紙40×60px、タイトルは残り幅、状態と点数は次の行。
タイトルは2行まで、accessible nameは全文。順位と点数の巨大表示を避ける。
lib/ranking.tsを再利用。nullを除き0を含む。同点は1,1,3、表示順を安定させる。
画像なしでも枠とタイトルを保つ。既存のネタバレ・画像保護を維持。
読み込み/DB失敗/評価作品なしを区別。ランキング画像共有は追加しない。

### 統計 /stats

見出しと共有/情報更新の補助操作→4項目のsummary→実績と推定→月別クリア/状態分布→安全なタグ頻度。
summaryはPC4列/スマホ2列。1項目はラベル14px/数値24px/補足13px、強い装飾や巨大カードは不要。
図表はPC2列/スマホ1列、横棒で比較。トラックsecondary、塗りprimary等のcontrastがある組み合わせ。
calculateLibraryStatisticsの集計を再実装しない。実績時間と未着手の推定時間、評価済み件数、クリア日未設定件数を分ける。
既存html-to-imageの共有を維持。出力背景も白、私的メモ・設定・ボタンを出力範囲に入れない。
全画像失敗、情報更新中/失敗、共有失敗、0件を確認する。

### 設定 /settings と/about

最大760px。データとバックアップ→表示と言語→購入先→このアプリについて。
セクション間32px、項目行間16px、薄い区切り。個別設定を巨大なカードへ分割しない。
BackupManagerとPurchaseLocationSelectorをそのまま再利用し、見た目だけを揃える。
JSON出力、ファイル検証、追加/競合件数、既存保持を既定とした復元、失敗からの回復を保つ。
「バックアップ済み」を安全保証のように表示しない。保存先がこのブラウザ、端末間同期なしを短く説明。
EN/JA、画像ぼかし、背景解除/既存背景の復元、購入先追加/変更/削除を維持。
/aboutは既存事実とリンクを維持、同じ枠と文字組み。ログインやテーマ切替を新設しない。

## 9. 共通の空・エラー・安全性

- 空ライブラリ: まだ作品がありません + 作品を追加 + バックアップから復元(/settings#backup)。
- 条件あり0件: 条件に一致する作品がありません + 条件を解除。全件0件と混同しない。
- DB失敗: ライブラリを読み込めませんでした + 再試行。正常な空表示にしない。
- 外部情報失敗: 保存済みの作品と記録を残す。最新情報の取得だけ再試行。
- 画像なし/通信失敗: 同じ比率のプレースホルダーとタイトル。大量の壊れたアイコンを出さない。
- 画像ぼかしON: 未知のsexual値を含む現行安全性判定を継承。作品の年齢区分で画像判定を代用しない。
- ネタバレは初期非表示。既存lib/spoiler-safety.tsを通し、タグや共有にも漏らさない。
- 削除や復元は対象と影響が分かる確認。通常保存の隣に強い削除ボタンを置かない。
- 実API・実データでテストしない。既存fixturesと隔離BrowserContextを使う。

## 10. 合格基準

320/390/768/1024/1440px、日本語・英語、長いタイトル、表紙なし、ぼかし、空/失敗/正常、背景あり/なしで確認。
PC1440×1000とスマホ390×844の画像をPRへ。モバイル記録は390×667でも確認。
横幅だけでは合格にしない。文字の識別、クリック可能な44px領域、focus、保存バーの重なり、コントラストを確かめる。
保存→再読込→JSON出力→隔離環境に復元で全フィールドと0/null/750分の値が一致。
既存E2Eの配置前提は新仕様に合わせて更新できるが、同じ意味のデータ保護・操作確認を削らない。
対象Issueの意味のあるテストとnpm run check:review、必須CIのQuality checksを成功させる。
コード上の「できた」とスクリーンショットの一致を分け、未確認は未確認としてPRへ記載する。
